> 仓库：https://github.com/liuiopshaw/cdi-agent-collective

## 1. 起点：钙钛矿论文的 Agent 架构解读

对话始于对 Guo 等《AI-guided design of efficient perovskite solar cells
operationally stable at 100 °C》一文（含补充信息）的精读，回答三个问题：

1. **实现难度**：该多智能体架构工程上可实现，核心难点不在算法而在
   数据治理（描述符定义、来源留痕、归一化因子的冻结纪律）。
2. **向 CDI 迁移**：可以迁移，但不能照搬"发现导向"范式（见第 2 节）。
3. **可优化点**：原文架构在不确定性量化、负结果利用、机制层的可审计性
   方面有改进空间。

## 2. 用户需求的多轮收敛

用户的研究体系：**MXene 负载 Fe 纳米团簇作为 CDI 阳极，在一定电压下展现
远超已有 CDI 电极的活性氧/活性氯（ROS/RCS）催化性能，兼具脱盐与杀菌；
催化机制为已证实但未报道过的新机制**。

需求经过多轮关键澄清后收敛为：

- 从预测出发，但最终预测的材料与机制必须能对应已有的实验数据；
- 材料群不限于 Fe/MXene，要推广到更广泛的载体 × 活性中心组合；
- **不要**性能预测地图——没有精力做大量验证实验，最终只呈现自己已有的
  MXene@Fe 组合数据（与钙钛矿论文只呈现最终 champion 材料同构）；
- 核心诉求：让"新机制"的呈现更有说服力。

### 关键逻辑瑕疵的讨论（重要）

用户指出了朴素方案的两个矛盾，这直接塑造了最终架构：

1. 既然 AI 无法预测 MXene@Fe 的新机制，它凭什么把该组合从材料库中推出？
2. 既然 AI 对目标材料预测不准，对其他材料的预测凭什么可信？岂不是需要
   无数实验验证？
3. 其他材料预测"准确"只是因为数据库里本来就有数据，不是模型能力。

**由此确立的设计立场**：架构定位为**机制认证导向（mechanism-certification）**
而非"发现导向"。AI 的角色不是"预言家"，而是：(a) 在已知文献材料群上证明
描述符→性能的映射是可学习的（可证伪的锚点）；(b) 诚实标注 MXene@Fe 为
模型外推失败的**异常点（outlier）**；(c) 用描述符对比证明该异常无法由已知
描述符组合解释，从而把"预测失败"本身转化为"新机制必要"的证据。
即：**模型的残差认证新机制，而非模型的精度**。

## 3. 形成的架构方案

- **6 个 Agent（A0–A5）**：A0 中央协调（两轮查询协议，借鉴 Guo 等）、
  A1 数据抽取、A2 描述符/预测、A3 机制分析、A4 评估、A5 盲探/批评。
- **4 条管线（P1–P4）**：P1 文献→数据库；P2 锚定（以用户自有 MXene@Fe
  数据为 anchor record）；P3 机制认证；P4 评估与出图。
- **三层描述符 schema**：活性中心 / 载体 / 界面 + 条件与性能层；
  每条记录强制携带逐字证据引文与来源指针。
- **硬规则**：T1 不许猜测（缺失记 NR）；T2 逐字证据引文；T3 全程留痕
  （工具调用、模型版本、因子常数冻结后不可改）。
- **归一化因子 C_s / R_s**：类比 Guo 等的 F_s 稳定因子，把异质条件下的
  文献指标压缩为可比较因子，常数在 P1 试点标定后冻结。

### 文献查新

检索论文库/arXiv 确认已有团队在做类似"LLM 多智能体 + 材料文献抽取/预测"
构架（精读了 d6ra02168a 与 arXiv:2602.13312 两篇），结论：方向不冲突，
机制认证这一定位仍有差异化空间。

## 4. 代码仓库建设（已完成）

仓库 `cdi-agent-collective` 已在 GitHub 上线，**代码全程无中文字符**
（每轮提交前做 CJK 校验）。已实现：

- 完整的 6 Agent / 4 Pipeline 骨架、消息总线、共享状态；
- 描述符 schema + 质量门 `validate_record` + C_s/R_s 归一化；
- 模型池 + LOOCV 基准 + 残差异常认证（`ml/residual.py`）；
- **轻量工具层**：`Tool` / `ToolRegistry`（审计日志、异常转为 error
  payload 而非中断）、OpenAI function calling 支持、
  `BaseAgent.call_with_tools` 智能体循环（最多 6 步）；
- 四个内置工具：`corpus_search`（本地语料检索）、`dataset_query`
  （按载体族/元素过滤）、`compute_factor`（C_s/R_s）、`train_model`
  （CSV 上全模型池 LOOCV）；
- 演示：`run_demo.py`（离线 mock）、`run_tools_demo.py`（工具调用）；
- 另产出一份面向服务器续作的 roadmap md（每步交付物与逻辑闭环）。

设计要点：LLM 只决定"调什么工具、传什么参数"，**一切计算在代码侧确定性
执行**——直接回应"AI 预测可信度"质疑，每步可复现、可审计。

## 5. Phase 0.2：真实文献试抽（已完成）

用两篇同领域真实论文（袁勋/刘勇团队，Nature Communications）做语料试抽：

| | 文献 1 | 文献 2 |
|---|---|---|
| DOI | 10.1038/s41467-024-53174-9 | 10.1038/s41467-026-76780-1 |
| 体系 | Ag₂₈(GSH)₂₀ 团簇 locked 于 ZIF-67 | 无配体 Ag 团簇(~1.8 nm)@碳纳米纤维 |
| 定位 | 电化学杀菌（CEWD） | 脱盐+杀菌同步（CDIS） |
| 关键数据 | >99.99% 杀菌、40 循环衰减 0.75%、1.4 V | SAC 84.25 mg Cl/g、>4 log、200 循环保持 92.95% |

结果：两条记录均通过 P1 质量门；**总体字段命中率 67.1%**；
performance / provenance 层接近满分，**interface 层是最大缺口**
（25% / 75%）——印证机制字段在文献中客观稀疏，NR 纪律能如实反映。

### 试抽抓到的两个真实缺陷（已修复并推送，`7eaf2f6`）

1. **`charge_efficiency` 单位未约定**：百分数 vs 分数混用使 eta 项放大
   180 倍 → 统一为 [0,1] 分数，`validate_record` 加范围校验。
2. **`voltage_window` 自由文本破坏数值解析**：协议文本中的数字被误抓，
   产生 58.8 V 幻影窗口 → 拆分为数值字段 `voltage_max` + 文本字段
   `protocol`，删除脆弱的文本解析器。

修复后：19 项测试全部通过（含 2 项新回归测试）；Ag NCs@CNF 记录的
C_s 从荒谬的 22523 回到 **4.60**（与手算一致）。

### 已知未修问题（roadmap 候选）

- `rs_factor` 关键词打分无法处理 "~96 μM H₂O₂" 类定量报告（返回 None），
  需定量解析轨；
- Nature 双栏 PDF 文本提取丢空格，影响证据引文的逐字质量 → 后续优先
  采用出版商 HTML 全文，PDF 兜底。
